# Формат урока: справочник для авторов

Этот документ — полный справочник формата учебных материалов «Практики»: какие поля есть у урока,
шагов, заданий и тестов, как работают правила и разборы ошибок, как дать заданию файлы, базу SQLite,
`seed` и учебную симуляцию сети — и как проверить готовый урок.

**Все примеры YAML ниже дословно взяты из урока-образца**
[`scripts/fixtures/engine/content/lessons/fe/fe-l1.yaml`](../scripts/fixtures/engine/content/lessons/fe/fe-l1.yaml).
Этот урок проверяется настоящим Python (`node scripts/verify-content.ts --root scripts/fixtures/engine`),
а автотест `scripts/content-format-doc.test.ts` следит, чтобы примеры здесь не разошлись с ним.
Схема формата — [`src/content/schema.ts`](../src/content/schema.ts), дополнительные проверки при
чтении — [`build/content-lib.ts`](../build/content-lib.ts), выполнение кода —
[`src/runner/harness.py`](../src/runner/harness.py).

## 1. Где лежат материалы

| Файл | Что в нём |
| --- | --- |
| `content/course.yaml` | Карта курса: этапы, навыки, модули с планом уроков, лаборатории, проекты |
| `content/lessons/<модуль>/<id урока>.yaml` | Один урок — один файл (подпапка — для порядка, её имя ни на что не влияет) |

Урок попадает в приложение, только если он есть в плане своего модуля в `content/course.yaml`
(`modules[].lessons[]`: `id` и `title`) и `module` урока совпадает с этим модулем:

```yaml
modules:
  - id: fe
    number: 1
    part: deepening
    title: Справочный модуль
    why: Образец всех полей формата урока для авторов материалов.
    outcomes:
      - Скрипт проверки принимает этот урок без ошибок.
    hours: [1, 2]
    lessons:
      - id: fe-l1
        title: Файлы, модули, база и сеть
    practice: Шесть заданий на все возможности движка.
    mistakes:
      - Забыть превратить ввод в число.
    completion: Все задания решены.
    environment: browser
```

При сборке (`npm run content`, `npm run build`) YAML проверяется схемой и перекрёстными проверками
и превращается в JSON (`public/content/`). Ошибка формата останавливает сборку с понятным сообщением
(файл, поле, причина). Замечания (история короче 3 или длиннее 6 предложений, теория длиннее 350 слов,
последний шаг — не `recap`, меньше двух примеров у задания, где результат зависит от ввода или вызова) сборку не останавливают, но их видно в
выводе `npm run content` и в отчёте проверки.

## 2. Поля урока

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Латиница, цифры и дефис: `m7-l2`. Уникален в курсе |
| `module` | да | id модуля из `content/course.yaml` |
| `number` | да | Номер для людей, строкой: `"7.2"` (в кавычках — иначе YAML прочитает число) |
| `title` | да | Название урока |
| `objective` | да | Одна учебная цель — что ученик сможет после урока |
| `minutes` | да | Время в минутах, диапазон `[от, до]` |
| `prerequisites` | нет | id уроков, которые нужно пройти раньше (из плана курса) |
| `skills` | да | Навыки урока — id из `skills` в `content/course.yaml` |
| `environment` | да | `python` — код в браузере; `web` — веб-пример; `external` — внешний инструмент (чек-листы) |
| `story` | да | `title`, `text` (3–5 предложений), `fictional` — придумана ли история (так и показывается ученику) |
| `why` | да | Зачем это нужно: 1–2 предложения и пример |
| `usedIn` | да | Где это используется |
| `steps` | да | Шаги урока, не меньше двух; последний — обычно `recap` |

```yaml
id: fe-l1
module: fe
number: "1.1"
title: Файлы, модули, база и сеть
objective: Работать с файлами, своими модулями, базой SQLite и ответами сервера.
minutes: [25, 35]
prerequisites: []
skills: [fe-files, fe-modules, fe-http, fe-sqlite, fe-random, fe-basics]
environment: python

story:
  title: Кафе переезжает в программу
  fictional: true
  text: >-
    Лена ведёт учёт кафе в тетради, а цены — в таблице. Артём предлагает перенести всё в программу.
    Она будет читать цены из файла, заказы — из базы, а погоду для летней веранды — с сервера.
    Сегодня они соберут такую программу по частям.

why: Настоящие программы берут данные из файлов, баз и с серверов, а не только из ввода.
usedIn: Отчёты, боты, учёт заказов, любые программы, которые работают с данными.
```

Тексты (`body`, `statement`, `explanation` и другие) — простая разметка: абзацы, списки, `**жирный**`,
`*курсив*`, `` `код` ``, блоки кода в тройных обратных кавычках, ссылки `[текст](https://…)`.

## 3. Шаги урока

У каждого шага есть `id` (уникален в уроке), `type` и `title`. Виды шагов:

| `type` | Что делает ученик | Поля |
| --- | --- | --- |
| `theory` | Читает объяснение | `body`, `simpler`, `coach` |
| `example` | Смотрит разобранный код, меняет и запускает | `body`, `code`, `stdin`, `notes`, `tryIt`, `coach` + окружение |
| `predict` | Предсказывает вывод, потом видит настоящий запуск | `prompt`, `code`, `stdin`, `options`, `answer`, `answerIsNotOutput`, `explanation`, `coach` + окружение |
| `order` | Расставляет шаги по порядку | `prompt`, `items`, `before`, `explanation`, `coach` |
| `quiz` | Выбирает один ответ | `question`, `options`, `correct`, `explanation`, `coach` |
| `checklist` | Отмечает шаги во внешнем инструменте сам | `body`, `items`, `coach` |
| `exercise` | Пишет код, который проверяется тестами | `exercise` — см. [раздел 4](#4-задание-exercise) |
| `recap` | Вспоминает главное и отвечает своими словами | `points`, `question`, `answer` |

«Окружение» — поля `files`, `databases`, `seed`, `http` ([раздел 9](#9-окружение-запуска-файлы-модули-базы-seed-сеть)).
`coach` — короткая реплика наставника в боковой панели.

### theory

`body` — объяснение (ориентир — до 350 слов), `simpler` — объяснение попроще для кнопки «Объясни проще».

```yaml
- id: intro
  type: theory
  title: Данные вокруг программы
  body: >-
    Программа редко живёт одна: она читает файлы, подключает свои модули, берёт данные из базы
    и с сервера. В этом уроке всё настоящее, кроме сети: ответы сервера записаны заранее.
  simpler: Программа берёт данные не только из ввода, но и из файлов, базы и интернета.
  coach: Сначала посмотри примеры, потом пробуй сам.
```

### example

`code` — код примера (ученик может менять и запускать его), `stdin` — ввод для `input()`,
`notes` — пояснения к строкам (`line` — номер строки, не больше числа строк кода; `text`),
`tryIt` — что изменить и запустить снова. Проверка материалов требует, чтобы пример выполнялся без ошибок.

```yaml
- id: show-file
  type: example
  title: Чтение файла
  body: Файл `menu.txt` лежит рядом с программой — его содержимое видно в блоке «Файлы задания».
  code: |-
    with open("menu.txt", encoding="utf-8") as file:
        for line in file:
            print(line.strip().upper())
  files:
    menu.txt: |
      чай
      кофе
  notes:
    - line: 1
      text: Файл открывается по имени — он в той же папке, что и программа.
    - line: 3
      text: strip() убирает перевод строки в конце.
  tryIt: Убери `.upper()` и запусти снова.
```

### predict

`prompt` — вопрос, `code` — код, `answer` — что выведет программа. Ответ проверяется запуском:
он должен совпасть с выводом программы (пробелы в конце строк и пустые строки в конце не учитываются)
или с тем, что видно в консоли вместе с приглашениями `input()`. `options` — варианты ответа
(необязательно; `answer` должен быть одним из них). Если ответ — не вывод (ошибка, бесконечный цикл),
отметь `answerIsNotOutput: true`: тогда проверка сверяет только тип ошибки, если он назван в ответе
(`Ошибка FileNotFoundError`), а для намеренно бесконечного цикла ответ должен об этом говорить
(«будет работать бесконечно»).

```yaml
- id: guess-missing
  type: predict
  title: Файла нет
  prompt: Файла `notes.txt` рядом с программой нет. Что произойдёт?
  code: |-
    with open("notes.txt", encoding="utf-8") as file:
        print(file.read())
  options: ["Выведется пустая строка", "Ошибка FileNotFoundError"]
  answer: Ошибка FileNotFoundError
  answerIsNotOutput: true
  explanation: Открыть на чтение можно только существующий файл.
```

Прогноз со случайными числами — через `seed` (см. [9.4](#94-seed--повторяемые-случайные-числа)):

```yaml
- id: guess-dice
  type: predict
  title: Кубик с seed
  prompt: Перед запуском вызывается `random.seed(7)`. Что выведет программа?
  code: |-
    import random

    print(random.randint(1, 6), random.randint(1, 6))
  seed: 7
  answer: "3 2"
  explanation: С одним и тем же seed «случайные» числа каждый раз одни и те же.
```

### order

`items` — пункты (не меньше трёх, `id` и `text`) в правильном порядке; в интерфейсе они перемешиваются.
Если порядок допускает варианты, задай `before` — пары `[a, b]` («a раньше b»); тогда засчитывается
любой порядок, где выполнены все пары.

```yaml
- id: plan-request
  type: order
  title: Порядок запроса
  prompt: Расставь шаги работы с сервером по порядку.
  items:
    - id: send
      text: Отправить запрос с timeout
    - id: status
      text: Проверить код ответа
    - id: parse
      text: Разобрать JSON
    - id: show
      text: Показать результат
  explanation: Пока код ответа не проверен, разбирать JSON рано — в ответе может быть ошибка.
```

### quiz

`options` — не меньше двух вариантов, `correct` — номер верного, **с нуля**.

```yaml
- id: quiz-seed
  type: quiz
  title: Зачем seed
  question: Что даёт `random.seed(7)` перед бросками кубика?
  options:
    - Числа становятся больше
    - Каждый запуск даёт те же «случайные» числа
    - Кубик перестаёт быть случайным навсегда
  correct: 1
  explanation: seed задаёт начальное состояние генератора — последовательность повторяется, и программу можно проверить.
```

### checklist

Для уроков о внешних инструментах (редактор, терминал): ученик отмечает пункты сам, автопроверки нет.
У пункта — `id`, `text` и необязательный `help` («Если не получается»).

```yaml
- id: try-locally
  type: checklist
  title: То же на своём компьютере
  body: Повтори чтение файла у себя — там файлы настоящие.
  items:
    - id: create-file
      text: Создай рядом с программой файл `menu.txt` с двумя строками.
    - id: run-program
      text: Запусти программу из примера командой `python main.py`.
      help: Если Python не находит файл, проверь, что терминал открыт в папке с программой.
```

### recap

`points` — главное (не меньше двух пунктов), `question` — вопрос на понимание, `answer` — ответ наставника.

```yaml
- id: recap
  type: recap
  title: Итоги
  points:
    - Файлы урока лежат рядом с программой, каждый запуск получает их заново.
    - Запросы в уроках — учебная симуляция, настоящих запросов нет.
  question: Почему в запросе к серверу нужен timeout?
  answer: Без timeout программа может ждать ответа вечно, если сервер завис.
```

## 4. Задание (exercise)

Шаг `type: exercise` содержит поле `exercise`:

| Поле | Обязательно | Что это |
| --- | --- | --- |
| `id` | да | Уникален во всём курсе: по нему хранится прогресс ученика |
| `kind` | да | `repeat` — повтори приём, `modify` — измени условие, `write` — реши сам, `fix` — найди ошибку, `read` — прочитай код |
| `title` | да | Название; не должно раскрывать решение |
| `statement` | да | Условие |
| `input`, `output` | нет | Коротко: входные данные и ожидаемый результат (показываются отдельными карточками) |
| `constraints` | нет | Ограничения — ученик отмечает их для себя, это не проверка |
| `filename` | нет | Имя файла с кодом ученика, по умолчанию `main.py` (см. [9.2](#92-свои-модули-filename-и-import-в-тестах)) |
| `files`, `databases`, `seed`, `http` | нет | Окружение запуска — [раздел 9](#9-окружение-запуска-файлы-модули-базы-seed-сеть) |
| `starterCode` | да | Стартовый код в редакторе; не должен проходить проверку |
| `tests` | да | Тесты, хотя бы один с `example: true` — [раздел 5](#5-тесты) |
| `rules` | нет | Требования к устройству кода — [раздел 6](#6-правила-по-устройству-кода-rules) |
| `criteria` | да | Критерии проверки для человека («Как проверяется решение») |
| `hints` | да | Ровно три подсказки: вопрос-наводка, пример на другом материале, почти решение. Первая не должна содержать строк решения |
| `solution` | да | `code` — эталон, `explanation` — почему он работает |
| `wrongSolutions` | да | Типичные неверные решения — [раздел 8](#8-неверные-и-другие-верные-решения) |
| `altSolutions` | нет | Другие верные решения |
| `mistakes` | нет | Разборы типичных ошибок — [раздел 7](#7-разборы-типичных-ошибок-mistakes) |
| `afterPass` | нет | Что получилось и одно уместное улучшение — после успешной проверки |
| `skills` | да | Навыки задания (id из `content/course.yaml`) |
| `timeLimitMs` | нет | Лимит времени на один тест, мс (по умолчанию 3000) |
| `noHintsBeforeAttempt` | нет | Самостоятельная работа: подсказки и решение открываются только после первой проверки |

Небольшое задание целиком — с тестами, `seed`, другим верным решением, неверным решением и разбором:

```yaml
- id: practice-dice
  type: exercise
  title: Практика 6
  exercise:
    id: fe-dice
    kind: write
    title: Два кубика
    statement: >-
      Брось два кубика — два вызова `random.randint(1, 6)` — и выведи сумму. Проверка задаёт seed,
      поэтому «случайные» числа при каждом запуске одни и те же.
    seed: 7
    starterCode: |
      import random

      # брось два кубика и выведи сумму
    tests:
      - id: t1
        kind: io
        example: true
        expected: "5"
      - id: t2
        kind: io
        title: Другой seed
        seed: 5
        expected: "8"
    criteria:
      - Выводится сумма двух бросков randint(1, 6).
    hints:
      - Сколько кубиков бросают — и сколько раз нужно вызвать randint?
      - Пример с монеткой — `side = random.choice(["орёл", "решка"])`.
      - Вызови random.randint(1, 6) два раза и выведи сумму.
    solution:
      code: |
        import random

        first = random.randint(1, 6)
        second = random.randint(1, 6)
        print(first + second)
      explanation: Каждый вызов randint — отдельный бросок.
    altSolutions:
      - code: |
          import random

          print(sum(random.randint(1, 6) for _ in range(2)))
        note: Два броска в одной строке.
    wrongSolutions:
      - code: |
          import random

          print(random.randint(2, 12))
        note: Один бросок от 2 до 12 — это не два кубика.
        expectMistake: one-roll
    mistakes:
      - id: one-roll
        when:
          codeIncludes: randint(2, 12)
        why: Сумма двух кубиков распределена иначе, чем одно число от 2 до 12, — 7 выпадает чаще, чем 2.
        try: Брось каждый кубик отдельно — два вызова randint(1, 6).
    skills: [fe-random]
```

Конец задания с `afterPass` и `noHintsBeforeAttempt`:

```yaml
afterPass: Сумма считается из переменных — поменяй цену, и итог пересчитается сам.
skills: [fe-basics]
noHintsBeforeAttempt: true
```

## 5. Тесты

Общие поля тестов:

| Поле | Что это |
| --- | --- |
| `id` | Уникален в задании (на него ссылаются `failedTest` и отчёты) |
| `kind` | `io`, `call` или `assert` |
| `title` | Название для ученика; без него — «Пример N», «Граничный случай N» или «Проверка N» (N — номер теста) |
| `example` | Показывать в условии как пример |
| `edge` | Граничный случай |
| `stdin` | Ввод: каждая строка — ответ на один `input()`; если строк не хватит — `EOFError` |
| `files`, `databases`, `seed`, `http` | Окружение этого теста — дополняет окружение задания ([раздел 9](#9-окружение-запуска-файлы-модули-базы-seed-сеть)) |

Как идёт проверка: сначала правила (по тексту кода, без запуска), потом каждый тест отдельно — в новой
пустой рабочей папке, с новым пространством имён, программа ученика выполняется целиком как
`__main__`. Тесты не зависят друг от друга. Лимит — 3 с на тест (или `timeLimitMs`), вывод — до
20 000 символов. Зависшая программа останавливается, следующие тесты не запускаются.

### io — вывод программы

`expected` — ожидаемый вывод, `compare` — как сравнивать, `expectedLabel` — как описать ожидаемое
человеку, когда `expected` — шаблон.

`compare`:

| Поле | Что делает |
| --- | --- |
| `mode` | `lines` (по умолчанию) — построчно; `regex` — весь вывод целиком по регулярному выражению Python (`re.fullmatch`, точка совпадает и с переводом строки); `contains` — каждая непустая строка `expected` встречается в выводе |
| `ignoreCase` | Без учёта регистра |
| `ignoreSpaces` | Несколько пробелов подряд считаются одним, пробелы по краям строк не важны |
| `ignoreBlankLines` | Пустые строки не учитываются |

Всегда: `\r\n` считается `\n`, пробелы в конце строк и пустые строки в конце вывода не учитываются.
Проверяется только то, что напечатано в `stdout` (`print`); приглашения `input("…")` и вывод в
`stderr` в сравнение не входят.

```yaml
tests:
  - id: t1
    kind: io
    example: true
    expected: "Итого: 1950"
    compare:
      ignoreSpaces: true
  - id: t2
    kind: io
    title: Подпись и число
    expected: 'Итого: \d+'
    expectedLabel: «Итого:» и число
    compare:
      mode: regex
```

### call — значение функции

`call` — выражение Python, которое вычисляется после выполнения программы в её пространстве имён
(обычно вызов функции ученика); `expected` — ожидаемое значение как **литерал Python строкой**
(`"12"`, `"'текст'"`, `"[1, 2]"`, `"None"`, `"True"`); `floatTolerance` — допуск для дробных чисел.

Сравнение строгое по типам: `True` не равно `1`, список не равен кортежу, у словаря должны совпасть
ключи. Дробные числа сравниваются с допуском (по умолчанию 1e-9, или `floatTolerance` —
относительный и абсолютный); целое с дробным сравнивается как числа.

```yaml
tests:
  - id: c1
    kind: call
    example: true
    call: temperature("Казань")
    expected: "12"
  - id: c2
    kind: call
    example: true
    title: Города нет — ответ 404
    call: temperature("Атлантида")
    expected: None
  - id: c3
    kind: call
    edge: true
    title: Сервер не отвечает вовремя
    call: temperature("Медленск")
    expected: None
  - id: c4
    kind: call
    title: Другая погода
    call: temperature("Казань")
    expected: "-3"
    http:
      - url: https://api.example.com/weather?city=Казань
        json:
          temp: -3
  - id: c5
    kind: call
    edge: true
    title: Нет соединения
    call: temperature("Казань")
    expected: None
    http:
      - url: https://api.example.com/weather?city=Казань
        error: connection
```

### assert — проверка кодом

`code` — код с `assert`, который выполняется после программы в том же пространстве имён и в той же
рабочей папке: он видит переменные и функции ученика, файлы, которые программа создала, может
импортировать модуль ученика и заглянуть в журнал запросов `requests.calls`. `message` — что сказать
ученику, если проверка не прошла. `AssertionError` — тест не пройден; другое исключение в коде
проверки показывается как ошибка проверки.

```yaml
- id: t3
  kind: assert
  title: Файл с итогом
  code: |
    import os

    assert os.path.exists("total.txt"), "файла total.txt нет"
    with open("total.txt", encoding="utf-8") as file:
        assert file.read().strip() == "370"
  message: Программа записывает сумму в файл total.txt.
```

## 6. Правила по устройству кода (rules)

Правило проверяет текст программы (через `ast`), не запуская её. Все условия одного правила должны
выполниться; `message` — что сказать ученику, если не выполнено.

| Поле | Условие |
| --- | --- |
| `use` | Каждое из перечисленного встречается хотя бы раз |
| `avoid` | Ничего из перечисленного не встречается |
| `min` | `{имя: n}` — встречается не меньше n раз |
| `max` | `{имя: n}` — встречается не больше n раз |
| `dependsOn` | `{переменная: [имена]}` — значение посчитано из этих переменных |
| `fromNumbers` | `{переменная: [числа]}` — значение посчитано формулой из переменных с этими числами |

```yaml
rules:
  - id: from-variables
    fromNumbers:
      total: [540, 3, 330]
    message: Посчитай total из переменных price, count и drink, а не готовым числом.
  - id: print-total
    dependsOn:
      print: [price, count, drink]
    message: Выведи сумму, посчитанную из price, count и drink.
  - id: one-print
    use: [call:print]
    avoid: [For, While]
    max:
      "call:print": 1
    message: Хватит одного print, без циклов.
```

**Имена для `use`, `avoid`, `min`, `max`** — это имена классов узлов модуля `ast` (Python 3.14) и вызовы:

- Инструкции: `Assign`, `AugAssign`, `AnnAssign`, `If`, `For`, `While`, `Break`, `Continue`, `Pass`,
  `FunctionDef`, `Return`, `Lambda`, `ClassDef`, `Try`, `ExceptHandler`, `Raise`, `Assert`, `With`,
  `Import`, `ImportFrom`, `Global`, `Nonlocal`, `Delete`, `Match`, `Expr` (выражение как инструкция),
  `AsyncFunctionDef`, `AsyncFor`, `AsyncWith`, `TryStar`, `TypeAlias`.
- Выражения: `Call`, `Name`, `Constant`, `Attribute`, `Subscript`, `Slice`, `BinOp`, `UnaryOp`,
  `BoolOp`, `Compare`, `IfExp`, `NamedExpr`, `List`, `Tuple`, `Dict`, `Set`, `ListComp`, `DictComp`,
  `SetComp`, `GeneratorExp`, `JoinedStr` (f-строка), `FormattedValue` (`{…}` внутри f-строки),
  `Starred`, `Yield`, `YieldFrom`, `Await`, `TemplateStr`, `Interpolation`.
- Операции (тоже узлы, их можно считать): `Add`, `Sub`, `Mult`, `Div`, `FloorDiv`, `Mod`, `Pow`,
  `MatMult`, `BitAnd`, `BitOr`, `BitXor`, `LShift`, `RShift`, `And`, `Or`, `Not`, `USub`, `UAdd`,
  `Invert`, `Eq`, `NotEq`, `Lt`, `LtE`, `Gt`, `GtE`, `In`, `NotIn`, `Is`, `IsNot`.
- Прочее: `arguments`, `arg`, `keyword`, `alias`, `withitem`, `comprehension`, `match_case`, узлы
  шаблонов `match` (`MatchValue`, `MatchAs`, `MatchOr`…), контексты `Load`, `Store`, `Del`, корень `Module`.
- `call:<имя>` — вызов функции по имени: `call:print`, `call:input`, `call:int`, `call:len`, `call:open`,
  `call:range`, `call:sum`…
- `call:.<имя>` — вызов метода или функции через точку: `call:.append`, `call:.split`, `call:.strip`,
  `call:.get`. Модульные функции тоже считаются так: `random.randint(1, 6)` — это `call:.randint`,
  `requests.get(url)` — `call:.get` (не `call:random.randint`).

Имена чувствительны к регистру; неизвестное имя никогда не встретится (для `use` правило не выполнится,
для `avoid` — выполнится всегда). Правила по числу узлов плохо передают смысл: разные верные решения
дают разное число имён и присваиваний, поэтому для «посчитай из переменных» есть `dependsOn` и `fromNumbers`.

**`dependsOn`** — `{цель: [имена]}`. Цель — переменная или `print` (всё, что печатают вызовы `print`).
Имена — **исходные** переменные: те, которым присвоено готовое значение (число, текст, `input()`,
`int(input())`, выражение без других переменных). Промежуточные переменные в источниках не числятся:
если `total = price * count + drink`, то `print(total)` зависит от `price`, `count` и `drink`, а не от
`total`. Разбирается код верхнего уровня, условия, циклы, `try` и `with` (ветки объединяются);
тела функций не разбираются — `def` делает имя функции исходным значением.

**`fromNumbers`** — `{цель: [числа]}`: цель посчитана формулой, в формулах нет готовых чисел
(`price * 3` или `total += 5` не подходят — нужна переменная), и среди исходных переменных есть
переменные с каждым из чисел. `total = 1950` не проходит: значение ни из чего не посчитано.

Если разбор значений не удался (редкая конструкция), `dependsOn` и `fromNumbers` не проверяются —
чтобы не отклонить верный код ученика; остальные условия правила проверяются.

## 7. Разборы типичных ошибок (mistakes)

Разбор — заранее написанное объяснение, которое ученик видит вместо общего, когда срабатывает его
условие `when`.

| Поле | Что это |
| --- | --- |
| `id` | Уникален в задании; на него ссылается `expectMistake` |
| `when` | Условие — см. ниже; все указанные условия должны выполниться одновременно |
| `where` | Где искать (необязательно; по умолчанию — строка с ошибкой или строка из `codeRegex`/`codeIncludes`) |
| `why` | Почему так получилось |
| `try` | Что попробовать |
| `verify` | Как проверить (необязательно; по умолчанию — «нажми „Проверить“: тест такой-то должен стать зелёным») |

Условия `when` (хотя бы одно):

| Условие | Срабатывает, когда |
| --- | --- |
| `errorType` | Тип ошибки совпадает: `NameError`, `TypeError`, `SyntaxError`… Смотрится ошибка компиляции или первый тест с ошибкой. Ошибки учебного `requests` — по короткому имени: `Timeout`, `ConnectionError`, `HTTPError`, `JSONDecodeError` |
| `errorIncludes` | Текст ошибки (последняя строка или сообщение) содержит строку |
| `outputEquals` | Весь вывод теста (без пробелов в конце строк и пустых строк в конце) равен строке |
| `outputIncludes` | Вывод теста содержит строку |
| `codeIncludes` | Код ученика содержит строку |
| `codeRegex` | Код совпадает с регулярным выражением **JavaScript** с флагом `m` |
| `failedTest` | Тест с этим `id` не пройден |
| `failedRule` | Правило с этим `id` не выполнено |

Тонкости:

- Разборы проверяются по порядку, срабатывает **первый** подходящий — ставь конкретные раньше общих.
  Разборы смотрятся только если проверка не пройдена.
- Условия на ошибку и на вывод смотрят **один и тот же тест**. Если в разборе есть `errorType` или
  `errorIncludes` — это первый тест с ошибкой (или ошибка компиляции), и `outputEquals`/`outputIncludes`
  в том же разборе смотрят вывод этого теста (что успело напечататься до ошибки). Иначе — первый
  непройденный тест, и условия на вывод **не срабатывают**, если в нём программа упала, превысила
  лимит вывода или была прервана: оборванный вывод легко совпал бы с «не хватает строки».
- `failedTest`, `failedRule`, `codeIncludes`, `codeRegex` от выбора теста не зависят.
- `codeRegex` пишется в одинарных кавычках YAML — тогда обратная косая черта остаётся как есть.
  Флаг `m` значит, что `^` и `$` — границы **строк**. Поэтому `^(?!…)` проверяет каждую строку, а не
  весь код (и такое выражение отклоняется при сборке); «во всём коде нет …» пишется как `(?<![\s\S])(?!…)`.
- При зависании, выходе за лимит времени приложения или сбое самого Python разборы из материалов не
  показываются — ученик видит сообщение о слишком долгой работе.
- Порядок разбора для ученика: сбой среды → тайм-аут → синтаксическая ошибка (или подходящий разбор) →
  разбор из материалов → ошибка выполнения → лимит вывода → первый непройденный тест → требование к коду.

```yaml
mistakes:
  - id: hardcoded
    when:
      failedRule: from-variables
    why: Готовое число верно только для этого заказа — при другой цене программа ошибётся.
    try: Запиши total формулой из price, count и drink.
  - id: no-label
    when:
      outputEquals: "1950"
    why: Число верное, но в задании нужна подпись «Итого:».
    try: Выведи подпись и число — print("Итого:", total).
  - id: plus-count
    when:
      codeIncludes: price + count
    where: Строка с total
    why: Число пицц нужно умножить на цену, а не прибавить к ней.
    try: Замени первый + на *.
    verify: 'Нажми «Проверить» — должно получиться «Итого: 1950».'
```

Разборы по типу ошибки и по тесту (условие на ошибку стоит первым: при `errorType` подходящий тест
выбирается среди тестов с ошибкой):

```yaml
mistakes:
  - id: no-file-check
    when:
      errorType: FileNotFoundError
    why: Когда файла нет, open() останавливает программу ошибкой.
    try: Оберни чтение файла в try и поймай FileNotFoundError.
  - id: header-as-data
    when:
      errorType: ValueError
    why: Первая строка CSV — заголовок, и int("price") не получается.
    try: Пропусти заголовок — next(reader) или csv.DictReader.
  - id: no-total-file
    when:
      failedTest: t3
    why: Итог выводится, но файл total.txt не создаётся.
    try: Открой total.txt в режиме "w" и запиши туда str(total).
```

`codeRegex` в одинарных кавычках:

```yaml
mistakes:
  - id: no-empty-check
    when:
      errorType: TypeError
    why: Когда таблица пуста, fetchone() возвращает None, а его нельзя разложить на item и price.
    try: Проверь результат fetchone() на None до того, как его использовать.
  - id: ascending
    when:
      codeRegex: 'ORDER BY price(?!\s+DESC)'
    why: ORDER BY без DESC сортирует по возрастанию — первым идёт самый дешёвый заказ.
    try: Добавь DESC после ORDER BY price.
```

## 8. Неверные и другие верные решения

**`wrongSolutions`** — типичные неверные решения (хотя бы одно). Ученику они не показываются: по ним
проверка материалов убеждается, что тесты и правила ловят ошибку и что ученик увидит нужный разбор.

| Поле | Что это |
| --- | --- |
| `code` | Код неверного решения |
| `note` | Что в нём не так (для автора и отчёта проверки) |
| `expectMistake` | `id` разбора, который должен сработать; `null` — не должен сработать ни один (ученик увидит общий разбор проверки). Если у задания есть `mistakes`, указывается у каждого неверного решения |

Проверка материалов требует: каждое неверное решение проваливает хотя бы один тест или правило (и
не из-за сбоя самой проверки), срабатывает именно `expectMistake`, а каждый разбор из `mistakes`
срабатывает хотя бы на одном неверном решении (иначе — предупреждение).

**`altSolutions`** — другие верные решения (`code`, `note`): каждое должно пройти все тесты и правила,
как эталон. Так правила не отклоняют верный код, написанный иначе. Пример обоих — в задании
[раздела 4](#4-задание-exercise) (`fe-dice`).

## 9. Окружение запуска: файлы, модули, базы, seed, сеть

Каждый запуск — «Запустить» в задании, каждый тест, запуск примера и прогноза — идёт **в новой пустой
рабочей папке**:

1. в папку записываются учебные файлы (`files`) и создаются базы SQLite (`databases`);
2. туда же сохраняется код ученика под именем `filename` задания (по умолчанию `main.py`; у примеров и
   прогнозов — `main.py`);
3. папка становится текущей (`os.chdir`) и первой в `sys.path`, `random` получает `seed`, модуль
   `requests` — учебный, с ответами из `http`;
4. программа выполняется (для тестов `call` и `assert` — затем проверка, в той же папке);
5. всё возвращается как было: прежняя текущая папка и `sys.path`, модули, загруженные из папки,
   выгружаются из `sys.modules` (иначе `import` закешировался бы между тестами), папка удаляется.

В браузере это виртуальная файловая система Pyodide в памяти, при проверке материалов — тоже она
(процесс проверки не пишет на диск), в `quick-check.py` — временная папка на диске.

Поля окружения есть у задания, у теста, у `example` и у `predict`:

| Поле | Что это |
| --- | --- |
| `files` | Учебные файлы: `{путь: текст}` (UTF-8) |
| `databases` | Базы SQLite: `{имя.db: SQL-скрипт}` |
| `seed` | Целое число для `random.seed()` перед запуском |
| `http` | Ответы учебной симуляции сети — список записей |

«Запустить» в задании использует окружение задания. Тест **дополняет** окружение задания:

- `files` и `databases` теста добавляются к заданию, файл с тем же путём заменяется, а значение `null`
  убирает файл или базу задания (например, чтобы проверить «файла нет»);
- `seed` теста заменяет `seed` задания;
- записи `http` теста добавляются, а запись с тем же методом и адресом заменяет запись задания.

**Файлы после запуска.** Файлы, которые программа создала или изменила, ученик видит под выводом
(«Запустить», пример, прогноз) и в подробностях теста: путь, «новый»/«изменён», размер и начало текста
(до 4000 символов; у двоичного файла, например базы, текста нет). Показывается до 20 файлов;
нетронутые учебные файлы и удалённые не показываются.

**Интерфейс.** В условии задания (и в шагах `example`/`predict`) есть свёрнутые блоки «Файлы задания»
и «База данных» (только чтение), а при `http` — заметная пометка «Сеть — учебная симуляция: ответы
заранее записаны, настоящих запросов нет» со списком адресов. Если у теста-примера свои файлы или
ответы, они показаны в карточке примера.

### 9.1. files — учебные файлы

Путь — относительный, через `/`, без `..`, `.`, пустых частей, `\` и `:`; подпапки создаются сами.
Файл не может совпадать с `filename` задания (там лежит код ученика) и не может служить «папкой» для
другого файла. Текст записывается как есть, в UTF-8: в коде урока открывай файлы с `encoding="utf-8"`.

```yaml
- id: show-file
  type: example
  title: Чтение файла
  body: Файл `menu.txt` лежит рядом с программой — его содержимое видно в блоке «Файлы задания».
  code: |-
    with open("menu.txt", encoding="utf-8") as file:
        for line in file:
            print(line.strip().upper())
  files:
    menu.txt: |
      чай
      кофе
  notes:
    - line: 1
      text: Файл открывается по имени — он в той же папке, что и программа.
    - line: 3
      text: strip() убирает перевод строки в конце.
  tryIt: Убери `.upper()` и запусти снова.
```

Файлы задания, свой файл у теста, проверка созданного файла и «файла нет» через `null`:

```yaml
files:
  prices.csv: |
    name,price
    чай,120
    пирог,250
starterCode: |
  import csv

  # прочитай prices.csv, выведи «Итого: …» и запиши сумму в total.txt
tests:
  - id: t1
    kind: io
    example: true
    expected: "Итого: 370"
  - id: t2
    kind: io
    title: Другие цены
    files:
      prices.csv: |
        name,price
        суп,300
        хлеб,40
        сок,95
    expected: "Итого: 435"
  - id: t3
    kind: assert
    title: Файл с итогом
    code: |
      import os

      assert os.path.exists("total.txt"), "файла total.txt нет"
      with open("total.txt", encoding="utf-8") as file:
          assert file.read().strip() == "370"
    message: Программа записывает сумму в файл total.txt.
  - id: t4
    kind: io
    edge: true
    title: Файла нет
    files:
      prices.csv: null
    expected: Нет файла prices.csv
```

### 9.2. Свои модули: filename и import в тестах

Код ученика лежит в рабочей папке под именем `filename`, поэтому `assert`-тест может сделать
`import` модуля ученика — как другой файл проекта. Учебные модули (`files` с `.py`) тоже импортируются.
Помни: `import` выполняет код модуля заново (программа уже выполнилась как `__main__`), поэтому
пример использования в модуле прячут под `if __name__ == "__main__":` — это и проверяет тест `a2`.
Между тестами модули выгружаются: у теста с другим учебным модулем `import` найдёт новый файл.
Ошибка внутри импортированного модуля ученика показывается в его строке, с именем `filename`.

```yaml
filename: prices.py
files:
  money.py: |
    def rub(amount):
        return f"{amount} ₽"
```

```yaml
tests:
  - id: t1
    kind: io
    example: true
    title: Запуск файла
    expected: 900 ₽
  - id: a1
    kind: assert
    title: Функция из модуля
    code: |
      import prices

      assert prices.with_discount(200, 50) == 100
      assert prices.with_discount(990, 0) == 990
    message: Функция with_discount из модуля prices возвращает цену со скидкой.
  - id: a2
    kind: assert
    title: Импорт без вывода
    code: |
      import contextlib
      import io

      buffer = io.StringIO()
      with contextlib.redirect_stdout(buffer):
          import prices
      assert buffer.getvalue() == ""
    message: При import prices модуль ничего не печатает — пример запускается только под if __name__ == "__main__".
```

### 9.3. databases — базы SQLite

Перед каждым запуском база создаётся заново SQL-скриптом (`sqlite3.executescript`), поэтому изменения,
которые сделала программа, до следующего теста не доживают. Имя — путь с окончанием `.db`. Ошибка в
SQL-скрипте — ошибка материалов: проверка сообщит «SQL-скрипт базы … не выполнился». Модуль `sqlite3`
работает и в браузере (он встроен в Python приложения, отдельно скачивать ничего не нужно), и при
проверке материалов.

```yaml
- id: guess-orders
  type: predict
  title: Запрос к базе
  prompt: Что выведет программа?
  code: |-
    import sqlite3

    connection = sqlite3.connect("shop.db")
    count, total = connection.execute("SELECT COUNT(*), SUM(price) FROM orders").fetchone()
    print(count, total)
  databases:
    shop.db: |
      CREATE TABLE orders (id INTEGER PRIMARY KEY, item TEXT, price INTEGER);
      INSERT INTO orders (item, price) VALUES ('чай', 120), ('пирог', 250);
  answer: "2 370"
  explanation: COUNT считает строки, SUM складывает цены.
```

У теста — своя база (пустая таблица — граничный случай):

```yaml
- id: t2
  kind: io
  title: Другие заказы
  databases:
    shop.db: |
      CREATE TABLE orders (id INTEGER PRIMARY KEY, item TEXT NOT NULL, price INTEGER NOT NULL);
      INSERT INTO orders (item, price) VALUES ('суп', 300), ('хлеб', 40);
  expected: "суп: 300"
- id: t3
  kind: io
  edge: true
  title: Заказов нет
  databases:
    shop.db: |
      CREATE TABLE orders (id INTEGER PRIMARY KEY, item TEXT NOT NULL, price INTEGER NOT NULL);
  expected: Заказов нет
```

### 9.4. seed — повторяемые случайные числа

`seed` — целое число; перед запуском вызывается `random.seed(seed)`, и «случайные» числа каждый раз
одни и те же — ответ прогноза и `expected` теста можно записать заранее. Последовательности одинаковы
в браузере и в обычном Python. Без `seed` числа случайные. Пример задания с `seed` у задания и у теста —
в [разделе 4](#4-задание-exercise), прогноз — в [разделе 3](#predict).

### 9.5. http — учебная симуляция сети

Настоящих сетевых запросов нет никогда. В программе ученика `import requests` всегда даёт учебный
модуль (даже если у задания нет `http`, и даже если настоящий `requests` установлен у автора в Python):
он отвечает только тем, что записано в `http`, а на всё остальное — ошибкой соединения.

Запись `http`:

| Поле | Что это |
| --- | --- |
| `url` | Полный адрес с `http://` или `https://`; query-параметры можно писать прямо в адресе |
| `method` | `GET` (по умолчанию) или `POST` |
| `status` | Код ответа, по умолчанию 200 |
| `json` | Тело ответа — любое значение JSON (объект, список, число, строка, `true`/`false`, `null`); `response.json()` вернёт его |
| `text` | Тело ответа текстом (вместо `json`) |
| `headers` | Заголовки ответа `{имя: значение}` |
| `error` | Вместо ответа — ошибка сети: `timeout` → `requests.Timeout`, `connection` → `requests.ConnectionError`; с `error` не указываются `status`, `json`, `text`, `headers` |

Как находится ответ: совпадают метод, адрес без query (схема и сервер — без учёта регистра) и
query-параметры как словарь — порядок не важен, а `params` из вызова добавляются к query адреса.
Так `requests.get("https://api.example.com/weather", params={"city": "Казань"})` найдёт запись
`https://api.example.com/weather?city=Казань`. Нет записи — `requests.ConnectionError` с сообщением
«в учебной симуляции нет ответа для GET https://…».

Что умеет учебный `requests`:

- `requests.get(url, params=None, headers=None, timeout=None)`,
  `requests.post(url, data=None, json=None, params=None, headers=None, timeout=None)`,
  `requests.request(method, url, …)`. Параметры `cookies`, `files`, `auth`, `allow_redirects`,
  `proxies`, `verify`, `stream`, `cert` принимаются и ни на что не влияют; неизвестный — `TypeError`,
  как в настоящем `requests`.
- Ответ (`requests.Response`): `status_code`, `ok` (код меньше 400), `reason` («OK», «Not Found»…),
  `text`, `content`, `headers` (без учёта регистра имён), `url` (с параметрами), `encoding`, `json()`,
  `raise_for_status()` — `HTTPError` «404 Client Error: Not Found for url: …» для 4xx и
  «Server Error» для 5xx. `bool(response)` — то же, что `ok`.
- Исключения — в `requests` и `requests.exceptions`: `RequestException` (предок всех, наследник
  `OSError`), `HTTPError`, `ConnectionError` (это **не** встроенный `ConnectionError`), `Timeout`,
  `JSONDecodeError` (ответ не JSON; он же наследник `ValueError`), `MissingSchema` (адрес без
  `https://`), `InvalidURL`.
- Журнал вызовов `requests.calls` — список словарей `method`, `url`, `params`, `json`, `data`,
  `headers`, `timeout` (как их передала программа). У каждого запуска журнал свой; `assert`-тест
  проверяет по нему, например, что задан `timeout`.
- Нет: `Session`, `put`/`delete`/`patch` (в `http` записываются только `GET` и `POST`), потоковой
  загрузки, настоящих соединений.

После запуска прежний `sys.modules["requests"]` возвращается на место.

Прогноз с ответом сервера:

```yaml
- id: guess-weather
  type: predict
  title: Ответ сервера
  prompt: 'Сервер отвечает `{"temp": 12}`. Что выведет программа?'
  code: |-
    import requests

    response = requests.get("https://api.example.com/weather", params={"city": "Казань"}, timeout=5)
    print(response.status_code, response.json()["temp"])
  http:
    - url: https://api.example.com/weather?city=Казань
      json:
        temp: 12
  answer: "200 12"
  explanation: Код 200 значит «всё в порядке», а json() превращает ответ в словарь.
```

Ответы задания — успех, 404 и тайм-аут:

## 10. Как проверить урок

1. **Загрузка и формат** — `npm run content`. Читает все YAML, проверяет схемой и перекрёстными
   проверками (уникальные id, навыки и уроки из плана, ссылки `failedTest`/`failedRule`/`expectMistake`,
   корректность `codeRegex`, пути и конфликты файлов окружения, повторяющиеся ответы `http`, `null` у
   теста только для существующего файла задания, первая подсказка и название не раскрывают решение,
   есть тест-пример, стартовый код не совпадает с решением) и собирает JSON. Ошибки останавливают сборку, замечания печатаются с «⚠».
   Код при этом не запускается.
2. **Запуск в настоящем Python** — `npm run verify:content` (Pyodide, тот же `harness.py`, что в приложении):

   ```bash
   npm run verify:content                     # все готовые уроки
   npm run verify:content -- m7-l2 m8         # уроки и модули по id
   npm run verify:content -- --json           # отчёт в JSON
   npm run verify:content -- --timeout 8000   # лимит на тест, мс (по умолчанию 5000)
   node scripts/verify-content.ts --root scripts/fixtures/engine   # материалы из другой папки
   ```

   `--root` — папка, **внутри которой** лежит `content/` (с `course.yaml` и `lessons/`); так проверяют
   черновик урока или урок-образец, не трогая курс. Параметры через npm пишутся после `--`.
   Сначала выполняется та же загрузка, что в пункте 1, — ошибки формата показываются до запуска кода.

   Что проверяется: тесты сами по себе (`call` — выражение, `expected` у `call` — литерал, код `assert`
   компилируется); эталон проходит все тесты и правила и укладывается в лимит приложения (больше
   половины лимита — предупреждение); стартовый код не проходит; каждое `altSolutions` проходит;
   каждое `wrongSolutions` не проходит и даёт свой `expectMistake`; неиспользованный разбор —
   предупреждение; `predict` совпадает с настоящим выводом; `example` выполняется без ошибок, пояснения
   ссылаются на существующие строки. Всё — с окружением из материалов (файлы, базы, `seed`, `http`).
   Код выхода: 0 — ошибок нет, 1 — есть ошибки, 2 — неверные аргументы.
3. **Быстрая самопроверка на обычном Python** — после `npm run content`:
   `python scripts/quick-check.py m7-l2` (или id модуля; `--root <папка>` — материалы, собранные в
   `<папка>/public/content`). Проще и быстрее, но главная проверка — `verify:content`.
4. **Посмотреть глазами** — `npm run dev` и урок в браузере: условие, блоки файлов и сети, запуск,
   подсказки, разборы.

## 11. Частые ошибки в YAML

- **Числа и `True` в `expected`.** `expected: 12` YAML прочитает как число, `expected: True` — как
  логическое значение, а нужна строка: `expected: "12"`, `expected: "True"`. Строка-литерал для `call`:
  `expected: "'текст'"`.
- **Двоеточие с пробелом внутри текста** (`Итого: 1950`, `if x: y`) — такой текст берётся в кавычки:
  `output: 'Строка «Итого: 1950».'`. То же для текста, который начинается с `{`, `[`, `*`, `&`, `!`, `%`, `@`, `|`, `>`.
- **Обратная косая черта** (`\d`, `\s`) — в одинарных кавычках: `'Итого: \d+'`. В двойных она
  начинает escape-последовательность YAML.
- **Код** — блоком `|` (сохраняет переводы строк и последний `\n`) или `|-` (без последнего `\n`).
  Длинный текст — `>-` (строки склеиваются через пробел).
- **Ключ с двоеточием** (`call:print` в `max`/`min`) — в кавычках: `"call:print": 1`. В списках
  (`use: [call:print]`) кавычки не нужны.
- **Пустое значение у теста** `prices.csv: null` убирает файл задания; пустой файл — `prices.csv: ""`.
