# «Практика» на телефоне (Android)

## Почему нельзя просто открыть компьютерный адрес

На компьютере приложение открывается по адресу `http://127.0.0.1:4173`. На телефоне адрес `127.0.0.1` (или `localhost`) указывает на **сам телефон**, а не на компьютер. Кроме того, для установки приложения и работы без сети нужен **service worker**, а браузер разрешает его только в защищённом контексте: по HTTPS или на локальном адресе того же устройства. Адрес компьютера в домашней сети вида `http://192.168.1.5:4173` защищённым не считается. Поэтому для телефона нужен HTTPS-адрес.

## Выбранная схема: статический HTTPS-хостинг GitHub Pages

«Практика» — полностью статическое приложение: уроки, Python (Pyodide) и прогресс работают в браузере, сервер не нужен. Поэтому подходит бесплатный статический хостинг с HTTPS. Выбран **GitHub Pages**, потому что:

- HTTPS включается автоматически;
- сборку и публикацию делает готовый сценарий `.github/workflows/pages.yml`;
- приложение работает из подпапки `https://<имя>.github.io/<репозиторий>/` — это уже учтено (переменная `BASE_PATH`).

Что важно понимать заранее:

- **Сайт будет публичным.** В нём нет личных данных: прогресс хранится только в браузере каждого устройства, ключей API в приложении нет. Но уроки и код приложения увидит любой, у кого есть ссылка.
- **Прогресс между компьютером и телефоном не синхронизируется.** Переносится файлом: «Настройки → Прогресс и резервные копии → Сохранить в файл» на одном устройстве и «Выбрать файл» на другом.
- **ИИ-наставник с телефона.** Локальный сервер наставника (`npm run coach`) работает только на компьютере. С телефона его не видно — там работают «Подсказки курса». Для ИИ на телефоне понадобится отдельный удалённый адаптер с токеном доступа и лимитами (см. `docs/coach.md`).

Альтернатива с тем же результатом — Cloudflare Pages или Netlify (тоже бесплатный статический HTTPS-хостинг). Для них собирай командой `npm run build` с нужным `BASE_PATH` (для корня домена — `/`) и публикуй папку `dist`.

## Как опубликовать (один раз)

Эти шаги делаешь ты сам — публикация выполняется от имени твоего аккаунта.

1. Создай аккаунт на https://github.com (если его нет) и новый репозиторий, например `praktika`.
2. Загрузи в репозиторий папку проекта `praktika` (без `node_modules` и `dist` — они в `.gitignore`). Удобнее всего через GitHub Desktop или командами git.
3. В репозитории: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Открой вкладку **Actions**, выбери «Публикация на GitHub Pages» и нажми **Run workflow**. Через пару минут появится адрес вида `https://<имя>.github.io/praktika/`.
5. Открой этот адрес в Chrome на телефоне → меню «⋮» → **«Добавить на главный экран» / «Установить приложение»**.
6. В приложении: **Настройки → Работа без сети** → скачай Python (≈ 13 МБ, лучше по Wi-Fi) и нужные модули. После этого уроки открываются и проверяются без интернета.

Обновления: после каждого изменения в ветке `main` сайт пересобирается сам. Приложение на телефоне покажет «Доступна новая версия — Обновить»; прогресс при обновлении сохраняется.

## Что проверено, а что нет

- Проверено на ПК (Microsoft Edge, собранная версия): установка service worker, скачивание Python и модуля, открытие урока и проверка кода **без сети**.
- Проверена мобильная вёрстка в эмуляции Android (Chromium, 390 и 320 px, сенсорный ввод).
- **Не проверено на реальном Android-устройстве:** скорость первой загрузки Python, расход памяти, поведение экранной клавиатуры в редакторе, установка на главный экран. Сделай это после публикации: открой урок, нажми «Проверить», затем включи режим полёта и повтори.
- Сборка с подпапкой (`BASE_PATH=/praktika/`) проверена локально.

## Если понадобится APK

Приложение можно упаковать в Android-пакет через Capacitor, используя тот же веб-интерфейс. Это не нативная переработка: отдельно нужно проверить WebView (поддержка WebAssembly и Web Worker), экранную клавиатуру, хранение данных, сборку и подписание пакета. Пока PWA закрывает задачу, APK не нужен.
